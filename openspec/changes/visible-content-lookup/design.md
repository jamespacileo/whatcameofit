# Design

## Corpus corrections (15 November 2026)

The corpus reproduced unrelated-post contamination on Threads, Instagram, Telegram and TikTok. Platform detail readers now establish identity first: exact Telegram channel/message ID, matching Instagram/Threads public post metadata, and a visible TikTok item bound by permalink or canonical initial-item identity. TikTok may use its matching public caption when playback fails. Missing identity does not fall back to the whole page. Media inspection uses the same bound scope, and selection retains precedence.

Identification now distinguishes therapeutic reporting from incidental financial, supply, legal and company-profile mentions. It chooses one main intervention-condition pair, retains genuine combinations, and explains ambiguous roundups rather than concatenating their interventions. An explicitly stated everyday target is sufficient; a missing target is not inferred from the drug's identity. Both result caches move to version 3 so earlier erroneous answers cannot mask corrections.

The rerun records separate deployed address checks, live browser collection, replay of the actual collector on captured public DOM, and a bounded visible-frame check. All provider calls use the configured existing model. No full-video or installed-Safari verification is claimed. Structured per-row evidence lives in the corpus; submitted text, DOM and pixels remain temporary outside the repository and are deleted after verification. Rerun records override historical cache-derived spreadsheet verdicts without losing build or method provenance.

The local page reader remains first. activeTab capture is guarded by exact tab/window/URL, before and after capture, and excludes private or editing-sensitive contexts. Selected text prevents automatic capture. Pixels are cropped to primary visible media, resized with bounded JPEG output, and held only in memory. One image enters the existing reading call; record scoring remains text-only. No inference may treat the image claim as verified fact.

Local storage keeps ten successful answers for 24h with content fingerprints and checked-at dates. Visual fingerprints include the actual resized pixels, so canvas changes and same-URL media updates invalidate reuse; a local capture may be needed even on a cache hit. Search again bypasses reuse. Shared Cloudflare KV entries are keyed by a hash of the cleaned source URL and expire after 24h. Shared caching requires independent public source reading; mere possession of a permalink or screenshot is not proof that content is public. Reddit and other browser-only screenshots therefore work through the visual path and local reuse without being republished. No credentials, screenshots or report text enter cache or logs.

The source URL is separate from the website's fetch-url input. Metadata validation and bounded streaming JSON reads precede paid calls. No new browser host permissions are needed.

## Slow article lookup correction (14 November 2026)

The ScienceAlert tinnitus report reproduced a 32.8-second production lookup. Removing only the public page URL while retaining its paper links still took 31.9 seconds; removing those paper links reduced the same text lookup to 2.7 seconds. The model identified the text as not reporting a specific treatment. A deterministic reproduction showed that `lookUp` nevertheless waited indefinitely for a linked-paper or stated-record request. The installed Safari app also has no overall search deadline.

Return a non-treatment identification as soon as it is available while preserving overlap of useful requests for treatment reports. Bound publisher reads at ten seconds total and optional independent proof at three seconds, paper requests at five seconds, and registry requests at ten seconds including bodies. A failed public proof retains browser text and never authorizes sharing. A failed registry request remains a failure rather than a successful empty result.

Give each popup lookup one 45-second attempt deadline, including automatic visual fallback. Use shorter deadlines for the index (five seconds) and shared-cache probe (1.5 seconds). Attempt cancellation must prevent stale rendering, storage writes and subsequent requests while allowing an explicit retry with a fresh signal. Existing consent and screenshot rules remain in force. Do not automatically retry paid requests.

## Faster article lookups

Preserve the newer unchecked-paper warning and refusal to cache incomplete answers. This release optimises the live browser/service route; it does not change matching thresholds, treatment identification prompts, model/tier, budget, host permissions or publication rules.

The browser begins an eligible shared-result probe while it finishes local collection. Consent, current tab/URL, private-window and selection checks precede transmission. Local reuse still needs a matching content fingerprint; a shared result is explicitly dated and can be copied locally once the current fingerprint is known. Completed non-treatment results may be retained locally (24h, ten entries) and anonymously verified public non-treatment outcomes may be shared; failures, pending enrichment/core responses, unchecked papers and provisional negative text readings that still require an image are never cached. Cache versions isolate the new completeness contract.

A sufficiently substantial, structured ordinary article can be read from its words without automatically analysing a decorative photo. Social/media-only, short/ambiguous content, canvas/video and image-claim cues retain automatic visual fallback. An explicit Screenshot action remains available. Stable text-article fingerprints omit decorative-media layout changes; actual visual results continue to require a pixel fingerprint. No article text or image is persisted.

An opt-in NDJSON response sends {type:"core",result} only after the full clinical search and scoring have completed, followed by {type:"complete",result} when optional related papers/organisations finish. Errors before a core result are explicit error events. Existing JSON callers receive the complete original shape. The extension renders the completed core answer with plain loading text for additional research, appends enrichment, and keeps the core answer if enrichment/stream completion fails; incomplete streams are not cached. Closing/navigation/deadlines prevent stale updates and follow-up requests. One paid identification/scoring run serves both events.

Start enrichment and name-based registry search once identification is ready, while linked-paper requests finish. Registry work uses one queue to preserve source manners and stated/paper record priority when assembling candidates. Linked papers have a five-second aggregate allowance, at most three requests with starts at least 500 ms apart; a stalled first paper does not prevent later papers from starting. Count every unfinished paper and preserve the no-cache rule. Successful structured DOI/PubMed trial-number and public registry lookups can be cached for up to 24h with bounded cache I/O; errors/timeouts are never stored as empty matches. Do not persist abstracts, article text, credentials or reader identifiers.

Add stage durations and first-result/full-completion timings without content logging, for controlled comparisons. Saved-result and fresh-search timings are distinct. Existing 45-second client deadline and explicit Search again remain safety bounds rather than performance targets.
